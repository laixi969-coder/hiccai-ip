## 二、识别结构参考案例（原文点名）

原文用它们说明"**基础形象识别足够强**，才能跨类型延展"：

| IP | 原文点出的核心符号 |
|---|---|
| 哆啦A梦 | 铃铛／口袋／圆形轮廓 |
| 米奇 | 圆耳朵／白纽扣／红短裤 |
| 马里奥 | 红帽子／大胡子／M 标志／顶拳动作 |
| 皮卡丘 | 闪电尾巴／黑耳尖 |

**共性**（原文）：轮廓简单 / 比例稳定 / 结构清楚 / 符号明确 / 局部特征容易被记住。

> 即使只看到米奇的圆耳朵、皮卡丘的闪电尾巴，用户也能快速识别。这是它们能跨类型的**底层原因**。

**跨类型样本**：米奇、皮卡丘 —— 并不是一开始作为普通品牌吉祥物出现，而是先有内容、故事、角色关系和长期用户情感积累，后来才成为很强的品牌型 IP。

## 三、反面案例（原文点出的"做错的样子"）

| 反面情形 | 原文原话 |
|---|---|
| 品牌型做复杂了 | "明明需要被记住，却一直在追短期流行" |
| 产品型做成吉祥物 | "明明需要卖货，却做成了一个很稳的品牌吉祥物" |
| 文化型堆元素 | "很多项目一做文化 IP，就开始堆元素。建筑、纹样、服饰、图腾、历史人物、地方特产，什么都想放进去。最后看起来很有文化，但识别不清" |
| 文化型靠讲解 | "如果一个文化型 IP，必须靠长篇讲解，用户才知道为什么要买，说明它的视觉转译还不够直接" |
| 社交型做重了 | "明明需要用户传播，却把形象做得太完整、太沉重" |
| 周边先于品牌 | "如果品牌本身还没有一个清晰的品牌 IP，直接做周边，就很容易变成一批临时产品" |
| 内容型只做设定图 | 内容型 IP 不是靠一张设定图成立 |
| 类型混做 | "不能用做短期流行的表情包逻辑，去做长期的品牌符号。不能用做剧情角色的方式，去做文创产品" |
| 靠装饰做记忆点 | "IP 的记忆点，不是装饰出来的" |
| 靠换表情做性格 | "IP 的性格特征，不能只靠换表情，要长在原型结构里" |
| 靠加细节做识别 | "IP 细节越多，记忆越分散，轮廓才是第一识别" |

## 五、怎么用案例

1. **判型时**：在五型表找到最像的案例，问"用户的项目和它共享哪条判定理由？"
2. **定路径时**：按项目类型找对标（品牌型看天猫/TRON、产品型看 Labubu、系列看武当山、文创看辽博/新华书店）
3. **诊断时**：找同类案例看**设计侧重**，缺什么补什么
4. **别提错型**：不要把 Labubu（产品型）的标准套到天猫（品牌型）上。**两者都可以做周边，但设计路径完全不同。**
5. **文化型慎用潮玩案例**：原文对文化型没有点名具名案例，只有判定标准。讨论文化型以**标准**为准。
6. **AI 生成 IP 的对标**：他有近半改稿作品针对 AI 出图，可以直接对标"AI 生成 IP 改稿"这一类场景。
